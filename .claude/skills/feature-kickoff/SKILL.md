# 신규 기능 착수 (2026 투자학교)

**코드를 쓰기 전에** 이걸 먼저 한다. 이 프로젝트에서 되돌리는 데 가장 비쌌던 실패는 버그가 아니라 **없는 데이터를 있다고 가정하고 화면부터 만든 것**이었다.

## 0. 이 절차가 필요한 작업인가

**필요**: Phase 0 데이터 실측이 필요 / 새 화면·라우트 / 새 외부 소스 / 세션을 넘길 가능성.
**불필요**: 버그 1건 · 문구 교체 · 이미 설계된 기능의 후속 패치 → CLAUDE.md 기록만.

작은 작업에 문서 3개를 만드는 것도 낭비다(§2). 애매하면 사용자에게 물어라.

## 1. Phase 0 — 데이터 실측이 먼저 (가장 중요)

**어떤 소스도 실제로 호출해 보기 전엔 믿지 않는다.** 실측이 실제로 뒤집은 것들:

- **제미나이·챗지피티가 준 엔드포인트·서비스ID는 절반이 환각이었다.** 네이버 `dealRank`·서울 `tbGbCrPrg`·KRX Open API 공매도 → 전부 존재하지 않음. 코드 예시의 URL 경로 누락도 흔하다.
- **포털 페이지가 "서비스 종료"라 해도 API는 살아있을 수 있다**(서울 `upisRebuild` — 실측이 정답).
- **필드명·스케일·단위를 원문 라벨로 확인해라.** 실제로 틀렸던 것: `weight`→`etfWeight` · `firedBarsAgo`→`fired` · `^TNX`가 ×10이 아니라 퍼센트 그대로 · 네이버 투자자 매매동향이 백만원이 아니라 **억원**(100배 오류를 합계 검산이 못 잡았다 — 단위는 **원문 라벨 + 외부 독립 출처 절대값 대조**로만 검증된다).
- **통계 테이블은 축(CLS·ITM·GRP)이 테이블마다 다르다**(R-ONE) — 지역명이 행에 없으면 역사 지문으로 확정.
- **'연초 누계' 계열은 1월에 리셋된다** — 값이 연중 단조증가하면 누계다(차분 필요).
- **옛 지식으로 단정 금지.** "KR 어닝일은 Yahoo가 안 준다"·"SpaceX는 비상장"이 둘 다 실측에서 깨졌다.

실측 결과(성공·환각 판정 전부)를 `context-notes.md`에 **판정표로** 남긴다. 다음 세션이 같은 호출을 반복하지 않게.

## 2. 세 문서 스캐폴딩

`docs/<slug>/` 아래 세 파일. 실제 문서들은 9~30줄이다 — 길게 쓰지 마라.

### `plan.md`
```markdown
# <이모지> <기능명> — 설계 (YYYY-MM-DD)

## 목적
무엇을 해결하나. 학생이 어떤 결정을 더 잘 하게 되나.

## 데이터 (Phase 0 실측 결과)
- ✅ 쓸 수 있는 것: 소스·엔드포인트·키 필드·주기·이력 범위
- ❌ 못 쓰는 것 + 이유(유료/로그인/환각/지연) → 정직하게 제외한 부분
- 재사용: 기존 SSOT 무엇을 그대로 쓰나(신규 수집을 최소화)

## 계산 (결정론)
공식·임계값과 **그 숫자를 고른 근거**. AI는 서술만, 판정은 코드.

## 정직 캐비엇 (UI에 명시할 것)
표본 한계·지연·근사·"예측 아님".

## 구현
파일 목록(SSOT lib / API route / 컴포넌트) + 캐시 키 + 크론.
```

### `checklist.md`
```markdown
# <이모지> <기능명> 체크리스트

- [ ] Phase 0 데이터 실측 (판정표를 context-notes에)
- [ ] SSOT lib 작성 (순수 함수·결정론)
- [ ] API route (캐시 키·부분실패 박제 금지 가드)
- [ ] 컴포넌트 + 캐비엇 문구
- [ ] 독립 재계산 검증 (원천에서 다시 계산해 화면값과 대조)
- [ ] tsc → lint → check:build (`&&` 체이닝) → 배포
- [ ] CLAUDE.md 기록
```

**`context-notes.md`가 셋 중 가장 값나간다.** 다음 세션이 가장 비싸게 다시 알아내는 건 코드가 아니라 "왜 그 안을 버렸나"다. 기각 근거가 없으면 같은 안을 다시 제안하고 같은 실측을 다시 한다.

## 3. 앱 원칙과 충돌하는지 먼저 검토

새 기능을 붙이기 전에 자기 검열:
- **제1원칙(데이터 하드코딩 금지)** — 특정 시점 수치를 상수로 박으면 데이터가 바뀌는 순간 거짓말이 된다. 정적 참조 데이터(듀레이션·세법·정책 문서)만 예외이며 출처를 남긴다.
- **제1-b(디자인 값 하드코딩 금지)** — 색상 `TK` · 글자 크기 `FS` · 라운드 `RAD` · 여백 `SP`(`src/lib/theme.ts`).
- **제2원칙(SSOT)** — 같은 지표는 같은 출처·같은 계산·같은 관례(중위값 짝수 처리까지). **이미 SSOT가 있는 지표(PEG·배당·섹터·계절·수급)는 원천 API를 직접 때리지 마라.**
- **WHAT/WHEN 분리** — 기술 신호는 6축 점수·종목 선정에 **절대** 반영하지 않는다. 배지·근거·타이밍으로만.
- **자동매매 금지** — 조언까지. 체결·주문 없음.
- **가짜 정밀 금지** — 승률·점수를 지어내지 않는다. 표본수를 항상 병기하고, 없으면 없다고 한다.
- **일방적 매도 강요 금지** — 손실 종목에 단순 고평가만으로 손절을 강요하지 않는다.

기존 기능과 **중복인지** 확인한다. 이 프로젝트에서 외부 제안의 대다수는 이미 구현돼 있었고, 실제 갭은 하나둘이었다.

## 4. 착수 후

- 결정할 때마다 `context-notes.md`에 append(나중에 몰아 쓰면 이유를 잊는다).
- 검증은 **독립 재계산**으로 — 화면값을 원천에서 다시 계산해 대조. 캐시된 값을 캐시로 확인하는 건 검증이 아니다.
- 백테스트·승률이 나오면 `backtest-autopsy` 스킬로 4단 검사.
- 배포는 `deploy-verify` 스킬 절차.
- 끝나면 CLAUDE.md에 기록 + `docs/README.md` 목록에 한 줄 추가.
