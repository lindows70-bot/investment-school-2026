## 💥 2026-09-26 · Supabase 무료 한도 초과 → 읽기 전용·10분 정지 (app_cache 926 MB)

- **원인**: 캔들 캐시 키에 날짜가 있었다(`tech-chart-v1:{티커}:{시장}:{봉}:{KST날짜}`) — 읽는 쪽은 오늘 키만 보는데 지난 날짜 행을 아무도 지우지 않아 82일간 **47,129행**, app_cache 926 MB(DB 957 MB / 한도 500 MB). 신선도는 이미 30분 TTL(updated_at)이 판정하고 있었다 → `tech-chart-v2:{티커}:{시장}:{봉}` 로 한 행을 덮어쓴다.
- **정리하다 낸 2차 사고**: 디스크 84% 상태에서 `delete` 를 3,000행씩 반복 → 삭제 기록(WAL)이 남은 공간을 먹어 Postgres 가 멈췄다(57P03 → Unhealthy → 재시작 → 읽기 전용). 한 번에 지우는 delete 는 타임아웃으로 전부 롤백. temp 테이블 복사도 `No space left on device`.
- **해결**: 남길 35,923행을 PostgREST 로 로컬에 백업(읽기 전용에서도 읽기는 된다, 50행 페이지 — 300행은 statement timeout) → `set transaction read write; truncate public.app_cache;`(WAL 거의 없음, 공간 즉시 반환) → `resolution=ignore-duplicates` 로 복원(앱이 그새 쓴 새 키는 보존). 전체 DB 116 MB. 개수·갱신 시각 표본 대조 일치.
- **교훈**: ①캐시 키에 날짜를 넣으면 **지우는 장치 없이는 영구 누적**이다 — 신선도는 TTL 로. ②디스크가 찬 DB 에서 delete 는 공간을 더 쓴다 — **밖으로 백업 → truncate → 복원**. ③Supabase SQL Editor 는 스크립트 전체를 한 트랜잭션으로 감싸 `set session characteristics` 가 이번 실행에 안 먹는다 — `set transaction read write` 를 첫 줄에.
