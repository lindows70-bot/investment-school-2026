## 🔒 2026-09-25 · 스쿨 리그 API가 비로그인에게 학생 실명·수익률을 내주고 있었다

- **증상**: 비로그인 curl `GET /api/school-league` → 200. 학생 9명 실명·총수익률·보유종목·Core/Satellite 비중이 그대로 나갔다.
  `/school-league` **화면**은 middleware 가 막지만, API 는 서비스롤로 전체를 모아 세션 확인 없이 반환했다.
  middleware 주석의 전제("데이터 자체는 API가 401로 막지만")가 이 라우트에선 거짓이었다.
- **같은 노출**: `/api/school-index`(익명 집계 — 이름은 없지만 학생 4명 수준이라 반 보유 종목이 드러남, 주석상 의도도 '로그인 학생 대상').
- **수정**(`d9bc37a`): 두 라우트에 `day-movers` 와 같은 `createClient().auth.getUser()` 게이트 → 없으면 401. 서비스롤 집계는 로그인 사용자에게 그대로.
  호출부는 `SchoolLeague.tsx`·`SchoolIndexDashboard.tsx`(로그인 화면 브라우저 fetch)뿐 — 크론·서버 내부 호출 없음(`git grep` 전수).
- **검증**: 비로그인 curl 두 라우트 모두 401 `{"error":"unauthorized"}` / 로그인 Chrome 에서 league 200(학생 9·등록 6·인기 8), index 200(기준일 2026-09-25·6종), 리더보드 정상 렌더.
- **교훈**: 화면 보호(middleware) ≠ API 보호. 서비스롤을 쓰는 라우트는 **라우트 안에서** 세션을 확인해야 한다.
