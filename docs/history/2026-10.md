## 국내 EPS·PBR 도 PER 과 같은 기준으로(2026-10-01)

- **출발**: PER 을 최근 4분기로 바꾼 뒤 `eps` 만 직전 결산 연도로 남아 PER × EPS 가 주가와 안 맞았다. 같은 응답의 나머지 가격 파생 행도 함께 쟀다(필드 하나가 틀리면 나머지도 전수 확인).
- **실측**(`eps_probe.mjs` — 국내 보유 주식 21종, 앱 `/api/stock-info` vs 네이버 integration): **PBR 15종**이 20% 넘게 달랐다(6종은 50%↑ — 재무제표 PBR 행도 PER 행처럼 작년 말 주가 기준: LS ELECTRIC 6.61 vs 14.39 · 한미반도체 17.51 vs 34.04 · 대한광통신 4.34 vs 23.92 · 현대차2우B 0.67 vs 0.38). **EPS 12종**(4종은 50%↑ — 삼성전자 6,564 vs 22,292 · SK하이닉스 58,955 vs 224,313 · 두산 3,546 vs 17,343). **배당수익률·주당배당은 0종**(문제없음 — SK텔레콤만 네이버 쪽 값이 없음).
- **간편 화면엔 EPS·PBR 칸이 없다** — 영향은 분석 화면(종목 분석·내 자산·관심 종목·린치 적정주가·거장 위원회·가치 삼각형).
- **결정(선생님)**: PBR + EPS 둘 다 네이버 화면 기준으로. 화면의 기준 표기는 이번엔 하지 않음.
- **고침**: `stock-info` 국내 경로가 마지막에 `eps = integration 최근 4분기 EPS`·`pbr = integration PBR` 로 내보낸다. 응답에 `epsBasis`('ttm' · integration 을 못 받으면 'fy'). 예상이익 성장률 `(내년 예상 EPS − 결산 EPS) ÷ 결산 EPS` 와 배당성향 역산은 **결산 연도끼리** 견주는 계산이라 결산 EPS 로 그대로 둔다 → PEG·성장률은 변하지 않는다(하류에 forwardEps ÷ eps 로 성장률을 다시 만드는 곳이 없음을 grep 으로 확인).
- **바뀌는 것**: 분석 화면의 국내 린치 적정주가(EPS × 적정 배수)가 EPS 비율만큼 움직인다(삼성전자 약 3.4배 · SK하이닉스 약 3.8배). 거장 위원회의 'PBR ≤ 5' 체크가 일부 뒤집힌다(HD현대중공업 5.72 → 4.30 통과 · 대한광통신 4.34 → 23.92 불통과). 거장 위원회 캐시는 하루 단위(같은 KST 날)라 다음 날 새 값으로 계산된다 — 키는 올리지 않았다.
- **알고 남긴 것**: 이익이 정점인 경기순환주(SK하이닉스)는 최근 4분기 EPS 로 적정주가가 가장 높게 나온다 — 린치의 순환주 함정과 같은 방향. PEG 쪽은 기저효과 가드가 있지만 적정주가 쪽엔 없다.
- **검증**: `verify-naver-basics` 에 3건 추가(epsBasis = 'ttm' 이고 네이버 화면 EPS 와 같음 · PBR 3% 안 · **PER × EPS 가 지금 주가와 3% 안**).

## 린치 적정가를 한 함수로(2026-10-01)

- **증상**: 같은 종목의 '린치 적정가'가 화면마다 달랐다. SK하이닉스(주가 ₩1,828,000) — 린치 자동 분석 ₩2,691,756 · 매크로 터미널 ₩4,908,064 · 이익 차트(성장률 모델) ₩11,215,650.
- **조사**: 화면마다 EPS 와 배수가 따로였다.

  | 화면 | EPS | 배수 |
  |---|---|---|
  | 린치 자동 분석 | 종목 정보 최근 EPS | 패널 자체 표(`CAT_MULT`: 순환주 12 · 우량주 16…) |
  | 매크로 터미널 린치 라인 | EPS 이력의 마지막 값(SK하이닉스는 내년 예상 350,576) | `calcFairMultiple`(PER÷PEG, 분류 상한) |
  | 린치 이익 차트 | 최근 EPS | 모델 3종(성장률 50 상한 · 5년 평균 PER · 15) |
  | 이익선 트레이서 | EPS 이력 | 15 · 과거 중앙값 PER |

  배수표가 세 벌(`CAT_MULT` · `LYNCH_MULTIPLE_DEFAULT/CAP` · `lynch-eps-history` 의 `multipleMap`). 그리고 `calcFairMultiple` 의 PER÷PEG 식은 보유 28종 중 **24종이 분류 상한**에 걸린다 — 사실상 '분류별 상한 배수'로 동작한다.
- **결정(선생님)**: 설계안대로 · 배수는 지금 공용 함수 값 그대로(기본/상한 — 순환주 12/14 · 우량주 15/20 · 고성장주 25/30 · 저성장주 10/12 · 회생주 20/25 · 자산주 12/15).
- **고침**: `lynchAnalysis.lynchFairValue({ eps, pe, peg, growthPct, category, market, price })` → `{ fairPrice, eps, multiple, gapPct, jump, basis }`.
  - EPS = 종목 정보의 최근(trailing) EPS · 0 이하면 적정가 없음.
  - 배수 = `calcFairMultiple` 그대로. **이익 급증이면 상한이 아니라 분류 기본값**(PEG 가 0 에 붙어 상한까지 올라가는 것을 막는다 — SK하이닉스 14 → 12).
  - 린치 자동 분석(자체 표 삭제) · 매크로 터미널('현재' 노드의 EPS·배수 — 대시보드가 종목 정보 EPS 를 그대로 넘긴다. 적자 종목은 터미널의 기존 예상·매출 모드 그대로) · 이익 차트(진단 칸·KPI 의 적정가와 판정. 세 모델 버튼은 선을 그리는 비교 도구로 남기고 배지 문구를 '선을 그리는 배수(모델)'로) 가 이 함수만 부른다.
  - 세 화면 모두 이익 급증 판정에 같은 성장률(종목 정보 `earningsGrowth`)을 넘긴다 — 미국은 PEG 가 야후 직접값이라 PER÷PEG 와 다를 수 있다.
- **손대지 않은 것**: 이익선 트레이서(이미 '린치선 (EPS×15)'로 표기) · 어닝 터미널(PEG 를 바꿔 보는 시나리오 도구) · `lynch-eps-history` 의 `multipleMap`(매크로 터미널이 덮어쓴다) · 최일 패널·버핏 DCF·모닝스타(다른 방법론).
- **바뀌는 값**: 린치 자동 분석의 우량주가 16배 고정 → PER÷PEG(8~20) · 고성장주가 성장률 연동(15~30) → PER÷PEG(8~30) · 회생주 15 → 기본 20. 매크로 터미널은 예상 EPS → 최근 EPS.

## 경기순환주 정점 표시(2026-10-02)

- **왜**: 이익 급증 가드(PEG<0.3 & 성장>100%)는 성장률이 100% 이하인 정점 순환주를 못 잡는다 — 삼성전자(성장 33%)가 '12% 저평가'로 나왔다. 여러 해 평균으로 가격을 다시 재는 안은 실측에서 기각(위 절).
- **규칙**: 분류가 경기순환주이고, 최근 4분기 EPS 가 **확정 결산 연도 EPS 의 최고치보다 크면** peak. 가격·배수는 건드리지 않고, 주가가 적정가보다 낮을 때만 '저평가' 대신 이유 문장을 쓴다 —

## 이익선 트레이서 '현재' EPS 를 최근 4분기로 통일(2026-10-03)

- **증상**: 같은 SK하이닉스가 트레이서에선 '린치선보다 107% 위', 최근 4분기 EPS 를 쓰는 종목 정보·적정가 화면에선 '32% 아래'. 트레이서의 `currentEps` 가 **직전 결산 연도(2025) EPS 58,955** 였고, 최근 4분기는 224,313 이다(제2원칙 위반 — 같은 종목 다른 값).
- **실측(프로덕션, 수정 전)**: 000660 결산 58,955 vs TTM 224,313(이격 +106.7% → 약 +37%) · 005930 6,564 vs 22,292(+180% → 약 −17%) · NVDA 2.94(FY2025=2025-01 결산) vs 7.92(+430% → 약 +97%) · COHR 결산 −0.52 라 **적자 화면**이었는데 TTM 은 4.12(흑자 전환 뒤 — 선을 그릴 수 있다).
- **처방**: 라우트가 `/api/stock-info` 의 `fundamentals.eps`(KR=네이버 TTM `epsBasis:'ttm'` · US=야후 `trailingEps`)를 받아 `currentEps` 로 쓰고 `currentEpsBasis:'ttm'|'fy'` 를 응답에 싣는다. 못 받으면 결산 EPS 폴백 + `'fy'`. 캐시 키 `lynch-tracer` → `lynch-tracer-v2`(reader 는 라우트 한 곳). 화면은 KPI 라벨 '린치선 (최근 4분기 EPS×15)', 표 위에 "표의 EPS 는 결산 연도 실적이라 마지막 행과 다를 수 있다" 안내, 푸터에 기준 병기. 연도별 점·중앙 PER 은 결산 EPS 그대로(역사 축이라 바꾸지 않는다).
- **같은 화면 안의 두 기준**: 표 마지막 행(2025 결산 EPS × 15)과 KPI 린치선(최근 4분기 × 15)이 다른 값이다. 숨기지 않고 안내 문구로 밝혔다 — 한 표면에 축이 둘이면 병기한다는 규칙.
- **불변식**: `verify-lynch-fair.mjs` 에 트레이서 `currentEps === 종목 정보 eps`(000660·NVDA, basis 'ttm') 추가.
- **검증**: 프로덕션(e00e824a·073aa9f0) 실측 — 000660 현재 EPS 224,313(ttm) 이격 −45.3%(전 +106.7%) · 005930 22,292 −17.5%(전 +180%) · NVDA 7.92 +96.9%(전 +430%) · COHR 4.12 +445%(전 적자 화면). `verify-lynch-fair` 전부 통과(트레이서 EPS = 종목 정보 EPS 2종). 로그인 브라우저 대시보드 🔭 탭 SK하이닉스: KPI '린치선 (최근 4분기 EPS×15) ₩3,364,695', 안내 문구(11px 토큰), 푸터 기준 병기, 그리고 **이익 급증 가드가 처음으로 실제 종목에서 발동**(🟡 '이익이 한 해에 두 배 넘게 뛴 구간' — 결산 EPS 시절엔 선 위라 가드 사례가 없었다). 1280·768·375 페이지 가로 넘침 0. 375 에선 KPI 라벨이 두 줄(30px)이고 연도별 표는 기존 overflow 래퍼 안에서 가로 스크롤(이번 변경과 무관).

## 경기순환주 정점 판정 기준 — 3년 → 5년 · 미국 종목 확장(2026-10-03)

- **비대칭**: 정점 가드(`lynchFairValue.peak`)의 비교 기준 `fyEps` 를 종목 정보가 **네이버 연간 재무의 확정 3년(KR 전용)** 에서만 만들고 있었다. US 는 `fyEps: null` 이라 코히런트처럼 적자→급반등한 미국 종목은 판정 밖이었다.
- **Phase 0 실측(프로덕션 `/api/financials`)**: KR 확정 EPS 5년(000660 2021~2025 · 적자 2023 포함 · 005930 · 009540 전부 5년) · US 4~5년(NVDA·COHR·SPCX 2022~2025 — 2021 은 0=자료 없음 · XOM·TSM 2021~2025). 응답 0.5~2.6초, 서버 캐시 없음. 종목 정보 KR `fyEps.n` 은 전부 3.
- **처방**: `src/lib/fyEps.ts` 신설 — `fyEpsFromGrid(격자, yearKeys)`(순수: E 제외 · 0 은 자료 없음이라 제외 · 적자 연도는 n 에 포함 · 3개 미만 null) + `getFyEps(ticker, market, origin)`(app_cache `fy-eps-v1:{market}:{ticker}` 7일 → 없으면 재무 API 자기 호출 1회 → 결과 있을 때만 저장). 종목 정보 라우트가 KR·US(네이버 해외·야후 두 경로) 모두 이걸 쓴다. KR 은 재무 API 를 못 받으면 **네이버 3년 폴백**(n 을 문장에 밝히므로 거짓은 아니다). 두 번째 계산기를 만들지 않고 재무 API 격자(DART 환산 포함)를 그대로 쓴다 — 같은 종목 결산 EPS 가 화면마다 다른 값이 되지 않게.
- **소비자 변경 없음**: 린치 자동 분석·매크로 터미널·린치 이익 차트·트레이서 모두 종목 정보의 `fyEps` 를 읽으므로 자동으로 5년·US 로 넓어진다. 문장은 그대로 "최근 N개 결산 연도(from~to)".
- **비용**: 종목 정보 첫 호출(종목·7일당 1회)에 재무 API 1~2.6초 추가. 그 뒤 app_cache 1건 읽기.
- **불변식**: `verify-lynch-fair.mjs` 에 격자 규칙 3건 + 프로덕션 삼성전자 n≥5 · 엑슨모빌(US) n≥4 추가.
