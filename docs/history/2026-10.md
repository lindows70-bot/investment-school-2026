- **증상**: `/api/stock-price` 국내 종목의 fundamentals 가 통째로 비어 있었다(PER 'N/A' · 시가총액·52주·배당·EPS null). `/api/lynch-classify` 국내 경로도 PER·EPS·배당·시총이 전부 null 로 들어가 **업종 하나로만 분류**되고 있었고, 적자 기업을 회생주로 잡는 판정(EPS<0)이 죽어 있었다.
- **원인**: 네이버 `m.stock.naver.com/api/stock/{code}/basic` 응답에서 `per`·`eps`·`dividendYield`·`marketValue`·`high52week`·`low52week`·`industryCodeType` 이 **전부** 사라졌다(실측 키 목록 33개 — 시세·상태 필드만 남음). 9/29 에 52주, 9/30 에 업종을 각각 따로 발견해 고쳤는데, **같은 응답의 나머지 필드를 그때 전수 확인하지 않아** 이틀을 더 흘렸다.
- **왜 아무도 몰랐나**: 값이 null 이라 빌드·타입체크·화면이 전부 통과했다. 종목 정보(`stock-info`)는 재무제표·polling 경로라 정상이어서 간편 화면은 멀쩡했고, 분석 화면 대시보드는 국내 배당수익률을 0 으로 계산하고 있었다(제2원칙 위반 — 화면마다 다른 값).
- **고침**: 같은 종목의 `integration.totalInfos` 에 값이 그대로 있다(`per=12.25배`·`eps=22,292원`·`dividendYieldRatio=0.61%`·`marketValue=1,596조 341억`·`highPriceOf52Weeks`…). 공용 순수 파서 `lib/naverIntegration.parseNaverBasics` 를 만들어 stock-price·lynch-classify·stock-info(52주) 셋이 같은 파서를 쓴다. 옛 basic 필드는 돌아오면 폴백.
  - 문자열 → 숫자: `numOf`(N/A·'-' 는 null — 0 으로 만들지 않는다 · 적자 EPS 는 음수 그대로) · `wonOfJoEok`(조·억이 없으면 null — 단위를 짐작하지 않는다).
