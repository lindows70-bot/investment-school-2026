## 채택하지 않은 안과 이유 ← 가장 중요

- **회색을 더 밝히기** — 세 번째가 될 뻔했다. 실측 대비비가 이미 7~12:1 이라 **레버가 아니다.**
  2026-06·2026-08-22 두 번의 명도 개선은 성공했고, 남은 원인은 밝기가 아니라 크기였다.
  같은 처방을 반복하면 또 재발한다.
- **전 파일 fontSize 일괄 치환** — 제1-b 금지. 색상은 픽셀 불변이라 코드모드가 가능했지만
  글자 크기는 좁은 칩·표에서 레이아웃이 밀린다. **손대는 화면 단위로만** 이관한다.
- **DCF 철학 블록 삭제** — 지우지 않았다. 이 앱의 철학 서명이고, 문제는 그 존재가 아니라
  **매일 쓰는 메뉴가 그 아래에서 시작하던 것**이었다. 사이드바 하단(프로필 위)으로 내렸다.
  → 아카데미 페이지로 옮기는 안도 있었으나, 그 페이지는 뉴모피즘 문법이라 이식 시 이물감이 크고
    파일 2개를 건드려야 해서 보류. 사용자가 원하면 그때 옮긴다.
- **모바일 하단탭을 6~7개로 늘리기** — 탭이 늘수록 라벨이 줄고 터치 영역이 준다.
  대신 **'전체' 탭이 사이드바를 서랍으로 띄운다** → 탭 5개로 33개 항목 전부 도달.
  메뉴 정의가 Sidebar 한 곳에 유지되는 것도 이 안의 장점(탭 목록을 따로 관리하지 않는다).
- **탭 구조(대시보드 50탭) 재편** — 1단계에서 손대지 않았다. 탭 재편은 이미 세 번 했고
  세 번 재발했다. **대시보드가 답하는 질문 하나**를 먼저 정하지 않으면 네 번째가 된다(2단계 과제).

- **커밋 훅이 브리핑에서 색상 하드코딩 7줄을 지적** — `#7c8db0`·`#1b2130`·`#1a1f30`·`#33415588`.

## 2단계 결정 기록 (2026-09-04)

### 프리미티브를 5개 → 3개로 줄인 이유
계획서엔 `PageHead·Verdict·Section·Row·Note` 5개였으나 **3개만** 만들었다.
- `PageHead` — `Verdict` 의 eyebrow 가 같은 일을 한다. 둘을 두면 "제목은 어디에 쓰지"가 새 문제가 된다.
- `Row` — 자산 보유 행(35요소)과 브리핑 추천 카드(10요소)는 구조가 너무 달라, 지금 추상화하면
  props 10개짜리 괴물이 된다. **두 번째 소비자가 생길 때** 만든다(§2 단순성).

### `Verdict` 는 페이지당 하나 — 코드로 강제하지 않은 이유
마운트 카운터는 React StrictMode 이중 마운트에서 오탐이 나고, 한 줄 규칙 때문에 렌더 사이드이펙트를
넣는 건 배보다 배꼽이다. 컴포넌트 헤더 주석에 규칙을 적고 리뷰에서 본다.

### 화면검증이 잡은 내 결함 2건 (배포 전)
- 🔴 **"평가손익 ₩0 (0.0%)"** — 시세가 오기 전 `evalKrw` 가 매입가로 폴백해 손익이 0 이 됐다.
  footer 에 경고를 달아뒀지만 **헤드라인이 '본전'이라고 단언**했다 — *배지·툴팁은 숫자를 상쇄하지 못한다*.
  `priceStatus`(idle/loading/done/error)가 **이미 있었는데 안 쓰고 있었다** — '있는데 안 쓴 데이터' 재발.
  → 시세를 못 믿으면 **손익 숫자를 아예 그리지 않는다**. 대시보드도 같은 규칙으로 갈랐다.
  ⭐ 교훈: 폴백이 있는 값을 헤드라인에 올릴 땐 **폴백 발동 여부를 먼저 물어야 한다.**
     경고를 덧붙이는 걸로 끝내면 안 된다.
- 부호 두 종류 혼재(`−₩283만 (-8.6%)`) — `toFixed()` 는 하이픈, 금액은 마이너스기호.
  `Math.abs` + 부호 한 글자로 통일(자산·대시보드).

### 커밋 훅 오탐 수정 (scripts/precommit-guard.mjs)
신규 파일 `Screen.tsx` 가 차단됐는데 걸린 건 **주석 안의 hex**("구 카드 배경이 '#12151f' 였다"는 실측 근거).
주석의 hex 는 화면을 칠하지 않는다 → `isCommentLine()` 추가(줄 **시작**이 주석일 때만 제외).
검증: 주석만 있으면 exit 0, 실제 스타일 값(`#ff00aa`·`fontSize: 9`)은 exit 1.
⛔ `--no-verify` 로 우회하지 않았다 — **훅이 부정확하면 고치는 게 맞지, 끄는 게 아니다.**

### 승패 해부실 — `mine`(내 보유)을 Verdict 에서 뺀 이유
`mine.size` 는 **미로그인·조회실패·보유0종이 전부 0** 이라 셋을 구분하지 못한다
(이 화면엔 로그인 상태 state 자체가 없다). 모르는 걸 0 으로 그리면 거짓말이 된다.

### 알면서 안 고친 것 → 3단계
`weekly-report` 의 `pcol()` 이 **초록=상승·빨강=하락(미국식)** 이고 22곳에서 쓴다.
프로젝트 규약('주가 등락·내 손익'은 한국식)과 반대인 게 코드로 확인됐다.
그런데 헤드라인만 뒤집으면 **바로 아래 KPI 8종과 정반대로 읽힌다**(같은 화면 안 모순은 이 앱이 두 번 사고 낸 유형).
→ Verdict 도 같은 `pcol` 을 쓰게 두고, 규약 통일은 3단계에서 화면 단위로. *일괄 치환하지 말고 가려라.*

## 3단계 결정 기록 (2026-09-04)

### Pretendard 실측 판정표 (npm 레지스트리 + tarball 직접 측정)
| 항목 | 실측값 |
|---|---|
| 버전·라이선스 | 1.3.9 · **OFL-1.1** (상용 배포 가능) |
| variable 통짜 woff2 | **2,009 KB** — 학생 모바일 첫 로드에 부담 |
| variable dynamic-subset | **92조각 · 총 3.1MB** (조각당 31~37KB) · CSS 54.5KB |
| 판정 | 도입 가능. 통짜 대신 **dynamic-subset**(브라우저가 unicode-range 로 쓰는 글자 든 조각만 받음) |
| **실전송(도입 후 실측)** | 브리핑 **25조각 643KB** · 로그인 **8조각 203KB** — 통짜 2,009KB 대비 **68% 절감** |

### 도입 방식과 그 이유
- `next/font/local` 은 **unicode-range 분할을 대신해 주지 않아** 통짜(2MB)만 가능하다 → 정적 CSS 로 넣었다.
  `public/fonts/pretendard/` 에 CSS + 92조각 + `LICENSE.txt`(OFL 고지 의무).
  배포된 CSS 의 상대경로(`./woff2-dynamic-subset/…`)가 그대로 맞아 경로 수정이 필요 없었다.
- 인라인 스택 59곳을 **지우지 않고 `FONT_STACK` 으로 치환**했다. 지우면 상속에 의존하게 되는데
  포털·모달 예외를 일일이 확인해야 하고, 치환은 회귀 위험 0 이면서 다음 교체도 한 곳으로 끝난다.
- ⛔ **인쇄본은 제외**(printReport·ResearchReport `@page`) — 라이트 배경 인쇄물이라 시스템 한글이 적절하고,
  웹폰트를 인쇄 CSS 에 넣으면 오히려 안 실린다.
- `body` 에 `fontVariantNumeric: 'tabular-nums'` — Pretendard 는 tabular 를 제대로 지원한다(맑은 고딕은 안 먹었다).
- ⭐ 교훈: **웹폰트를 선언만 하고 로드를 확인하지 않으면 아무 일도 안 일어난다.**
  `document.fonts` 로 `loaded` 를 눈으로 봐야 한다 — 이 앱은 그걸 안 봐서 Inter 를 몇 달간 '쓰고 있다'고 믿었다.

### 순서 판단 — 폰트를 색보다 먼저 한 이유
처음엔 "색 먼저"라고 적었다가 뒤집었다. **색은 픽셀 불변이라 폰트 뒤에 해도 재검증이 필요 없지만,
폰트는 글자 폭을 바꿔 레이아웃을 흔든다.** 흔드는 것을 먼저 하고 한 번에 검증하는 게 맞다.
(다만 등락 색 규약 교정은 이미 픽셀 불변이라 폰트 전에 끝냈다 — 두 커밋이 서로를 가리지 않는다.)

### 모바일 — auto-fit 이 만능이 아니다
처방이 두 부류로 갈렸다. 이걸 구분 못 하면 데스크톱이 망가진다.
- **(가) auto-fit 이 이미 있고 하한만 큰 경우** → `minmax(min(N, 100%), 1fr)`.
  min() 안의 100%가 그리드 컨테이너 폭으로 해석돼 좁을 땐 트랙이 줄고, 데스크톱에선 N 을 그대로 고른다.
- **(나) 비율 그리드(6fr/4fr·3fr/2fr)** → auto-fit 은 **오답**. 비율이 소멸해 6:4 가 5:5 가 된다.
  미디어쿼리로 모바일에서만 1열로 접어야 데스크톱이 그대로 남는다.
→ `globals.css` 에 모바일 유틸 7개(.m-stack/.m-wrap/.m-1col/.m-full/.m-wauto/.m-hide/.m-scroll).
  인라인 style 위주라 화면마다 @media 를 둘 자리가 없었다. **!important 는 이 파일 밖에서 쓰지 말 것.**

### 색 — 일괄 치환하지 말고 가려라(실제로 그래야 했다)
`weekly-report` 의 `pcol()` 을 통째로 뒤집었으면 **3곳이 오히려 틀렸다** —
외국인·기관 순매수(:424,425)와 전월세 전환율 스프레드(:612)는 '가격'이 아니라 판정 지표다.
→ 함수를 둘로 갈랐다: `pcol`(등락·손익, 한국식) / `jcol`(판정, 초록=좋음).

**인쇄본에 두 번째 SSOT 가 숨어 있었다** — `printReport()` 의 `pc()` 24곳 + 막대 배경 +
범례 문구 "상승 초록/하락 빨강". 화면만 고쳤으면 학생이 뽑은 종이와 화면이 정반대가 됐다.
인쇄본은 흰 배경이라 다크 토큰을 못 써서 인쇄용 값을 따로 두고 `토큰예외:` 사유를 남겼다.
⭐ 교훈: **색 함수를 고칠 땐 그 화면의 인쇄·내보내기 경로를 함께 찾아라.**

- **코인 카드는 red→orange 단순 치환이 오히려 나빴다.** 5~10%=orange(주의) / ≥10%=red(위험) **2단 램프**라
  둘 다 orange 가 되면 경보 강도가 사라진다. → 램프를 한 칸씩 올렸다(없음 회색 / 안전 emerald / 주의 amber / 위험 orange).
  ⭐ 교훈: **토큰을 바꾸기 전에 그 색이 램프의 한 칸인지부터 봐라.**
- **승패 화면 4곳**(역배열·EPS↓·승률<50%) — **초록/빨강 짝 판정**이라 CLAUDE.md 가 명시적으로 허용한다.
  빨강만 주황으로 빼면 초록/주황이 되어 짝이 약해진다.
- **주간 ⑩ 리스크 등급**(적정 초록 / 주의 amber / 위험 red) — 같은 섹션에 등락이 없어 충돌이 없고,
  green→amber→red 는 그 자체로 읽히는 램프다.
- **`briefing` 실적 요약** — `summary = "컨센서스 -3% 미달 · 발표 후 주가 +4.1%"` 가 **한 문자열**인데
  `beat` 하나로 색이 칠해진다. 토큰만 바꾸면 '주가 +4.1%'가 경고색이 되어 **형태만 바뀐다**.

#### 🔬 화면 실측 검증이 찾아낸 것 (로그인 상태 · computed color)
**코드만 보고 끝냈으면 넷 다 놓쳤다.** 이 프로젝트가 "화면검증이 마지막 방어선"이라고 적어둔 이유다.

1. **내가 만든 회귀** — 인사이트 알림 warning 을 orange400 으로 옮기고 나니 대시보드에 거의 같은 주황이
   둘(#fb923c·#f97316)이 돼서, 리밸런싱 위젯의 `WARN_CLR` 도 orange400 으로 합쳤다. **그게 틀렸다.**
   바로 두 줄 위가 `SAT_CLR = TK.orange400` 이라 **같은 위젯 안에서 '경고'와 'Satellite 진영'이 한 색**이 됐다.
   → 되돌리고 `토큰예외:` 사유를 남겼다. ⭐ **토큰을 합치기 전에 그 파일이 그 토큰을 이미 무슨 뜻으로 쓰는지 봐라.**
2. **컴포넌트 레이어를 안 봤다** — 분류 워크플로에 page 파일 6개만 줬더니, 브리핑에 붙은
   `SwingStopAlertBanner`(손절선 이탈)·`YieldCurveAlertBanner`(금리 역전)의 빨강 경보가 통째로 빠졌다.
   화면에서 `🚨 희석 경보`(빨강)와 `🚀 +9.3% 올랐습니다`(빨강)가 나란히 보여서야 드러났다.
   → 둘 다 이동. `🔴 장단기 금리 역전` 의 이모지도 `⚠️` 로 바꿨다(색만 옮기면 한 줄 안에서 자기모순).
3. **브리핑 ⚔️ 승패 요약이 미국식이었다** — `🔺 오르는 = green400` / `🔻 떨어지는 = red400`.
   같은 화면 위쪽 DayMover 는 한국식(빨강=상승)이라 **한 화면에서 '오르는'이 두 색**이었다.
   `/win-lose` 가 이미 푼 문제인데 브리핑 쪽만 남아 있었다 → 칩은 한국식(빨강/파랑), 요인 대비값은 **명도**로
   (`betterSide` 로 slate100·900 vs slate300·600). 우열은 등락이 아니므로 색을 쓰지 않는다.
4. **`coreLoss` 막대 vs 그 막대의 툴팁** — 막대는 red400(손실)인데 툴팁은 red400 을 'Core 수익'으로 썼다.
   다른 탭도 다른 조건도 아니고 **호버하는 그 순간 같은 화면**이다 → `blue400`(한국식 손실).

#### 📰 실적 요약은 색이 아니라 문자열이 문제였다 (2026-09-05)
`summary = "컨센서스 -3% 미달 · 발표 후 주가 +4.1%"` 가 한 문자열인데 `beat` 하나로 칠해져,
**주가가 올랐는데도 '+4.1%'가 미달 색(빨강)을 입었다.** 토큰을 바꾸면 형태만 바뀐다 —
판정(좋다/나쁘다 = 초록/빨강)과 주가(한국식 = 빨강 상승/파랑 하락)는 **축이 다르므로 문자열을 갈라야** 끝난다.
→ `src/lib/earnResultsShared.ts`(문구 SSOT) 신설. 서버 `earnResults.ts` 는 appCache·캔들을 쓰는 서버 전용이라
   클라이언트가 직접 import 할 수 없어 파일을 나눴다. 화면은 두 조각을 각자의 축으로 칠한다.
검증: 옛 join 로직과 **108 케이스 전수 대조 diff=0**(summary 바이트 동일 → 캐시 키 범프 불필요) ·
   화면 실측은 실적 발표가 없는 날이라(`rowCount: 0`) **브라우저에서만 fetch 를 가로채 합성 2행**으로 렌더를 쟀다 —
   `컨센서스 +5.2% 상회` green400 + `발표 후 주가 -2.5%` **blue400**(예전엔 둘 다 초록이었다).
⭐ 교훈: **"색이 틀렸다"의 절반은 색 문제가 아니다.** 한 문자열에 축이 둘이면 색으로는 영원히 못 고친다.

#### 🔁 2차 감사 — 워크플로가 '0건'을 반환해도 0건이 아니다
컴포넌트 레이어까지 넣어 26파일을 감사했다. 결과는 `survivors: 0` 이었지만
**에이전트 70개 중 47개가 세션 한도로 실패**했다 — verify 단계가 통째로 안 돌아 audit 지적이 전부 버려진 것이다.
`journal.jsonl` 에서 **미검증 지적 44건을 복구**해 하나씩 코드로 재현 확인했다.
⭐ 교훈: **워크플로 결과의 빈 배열은 "없다"가 아니라 "못 봤다"일 수 있다.** failures 수를 먼저 읽고, 저널을 열어라.

복구한 지적 중 **재현이 확인된 20곳만** 고쳤다(near-identical-hue 파편화 14건은 ⛔ 일괄 치환 금지로 보류):
- **내 앞선 변경의 잔여물 3건** — 대시보드 경고 메시지의 `🔴`(카드는 이미 주황+⚠️), 브리핑 버핏 각주 `🔴`,
  쏠림 경고 상자의 red500 틴트(글자만 주황으로 옮기고 **상자를 빨강으로 남겨** 한 박스가 두 말을 하고 있었다).
- **미국식 등락 규약 4곳** — `FullCandleChart` 평단가 대비 손익(green/red) · `win-lose` 대전표 막대(green500/red500 →
  red500/blue500, 같은 카드 헤더와 정반대였다) · `signal-report` 방향어 '오르면'(초록)·'떨어지면'(빨강) 및 적중 칩 라벨.
- **음수 등락률을 빨강으로 찍던 곳** — `TimingBadge` '📉급락 -20%' 칩. 뜻이 경고이므로 orange400.
- **경고 red → orange 5곳** — 주간 ②·⑩ 배너, 희석 경보 **크롬과 NEW 배지**(3단 램프 칩은 유지 — 램프는 `TYPE_META` 뿐이다),
  비밀번호 오류 문구, 마켓 카탈리스트 '거래량 3배↑'(같은 칩 안에서 등락률 빨강과 겹쳤다).

⚠️ **남은 위험**: `amber400(#fbbf24)` 과 `orange400(#fb923c)` 이 인접하다 — red600 을 기각한 것과 같은 종류다.
지금 둘이 나란히 서는 자리(코인 램프 · 버핏 strong/watch)는 **라벨이 색을 보강**하고 있어 통과시켰다
('🚨 위험' vs '⚠️ 권장 5% 초과', '🏰 기업 변질' vs '👀 관찰'). **라벨 없는 자리에는 이 짝을 쓰지 마라.**
