## 채택하지 않은 안과 이유 ← 가장 중요

- **회색을 더 밝히기** — 세 번째가 될 뻔했다. 실측 대비비가 이미 7~12:1 이라 **레버가 아니다.**
  2026-06·2026-08-22 두 번의 명도 개선은 성공했고, 남은 원인은 밝기가 아니라 크기였다.
  같은 처방을 반복하면 또 재발한다.
- **전 파일 fontSize 일괄 치환** — 제1-b 금지. 색상은 픽셀 불변이라 코드모드가 가능했지만
  글자 크기는 좁은 칩·표에서 레이아웃이 밀린다. **손대는 화면 단위로만** 이관한다.
- **DCF 철학 블록 삭제** — 지우지 않았다. 이 앱의 철학 서명이고, 문제는 그 존재가 아니라
  **매일 쓰는 메뉴가 그 아래에서 시작하던 것**이었다. 사이드바 하단(프로필 위)으로 내렸다.
  → 아카데미 페이지로 옮기는 안도 있었으나, 그 페이지는 뉴모피즘 문법이라 이식 시 이물감이 크고
    파일 2개를 건드려야 해서 보류. 사용자가 원하면 그때 옮긴다.
- **모바일 하단탭을 6~7개로 늘리기** — 탭이 늘수록 라벨이 줄고 터치 영역이 준다.
  대신 **'전체' 탭이 사이드바를 서랍으로 띄운다** → 탭 5개로 33개 항목 전부 도달.
  메뉴 정의가 Sidebar 한 곳에 유지되는 것도 이 안의 장점(탭 목록을 따로 관리하지 않는다).
- **탭 구조(대시보드 50탭) 재편** — 1단계에서 손대지 않았다. 탭 재편은 이미 세 번 했고
  세 번 재발했다. **대시보드가 답하는 질문 하나**를 먼저 정하지 않으면 네 번째가 된다(2단계 과제).

## 임계값·선택 근거

- **FS 램프 11 / 13 / 15 / 18 / 22 / 28 / 36** — 하한 11px 은 '설명이 읽히는 최소'.
  인접 배율 1.18/1.15/1.20/1.22/1.27/1.29 로 전 구간 1.15배 이상, 0.5px 단 제거.
  구 램프는 670곳 중 **512곳(76%)이 아래 두 단(9.5·11)에 몰려** 토큰을 써도 본문이 작았다.
- **고정 노출 그룹 = 위 2개(📌 매일 · 💼 내 자산)** — 사이드바가 이미 '매일'로 선언한 것 + 자산.
  나머지 8그룹 25항목은 접되, **현재 화면이 접힌 그룹에 있으면 자동으로 펼치고 토글을 숨긴다**.
  → 그래서 active 판정을 `isActiveHref()` 로 분리했다(접기와 렌더가 같은 규칙을 써야 한다).
- **모바일 본문 하단 여백 96px** — 고정 탭바 실측 약 62px + 여유.
- **상단바 브랜드만 FS.body(15) 유지** — lg(18)로 올렸더니 375px 에서 '2026 투자학 / 교'로 줄바꿈.
  같은 이유로 사이드바 교장 배지를 브랜드명과 다른 줄로 내렸다.

## 검증에서 발견한 것

- **`FS is not defined` 런타임 오류인데 tsc 는 통과** — 소스가 아니라 `.next` 개발 캐시가 꼬인 것.
  dev 서버 재시작(`scripts/dev.js` 가 `.next` 삭제)으로 해소. 에러 문구만 보고 import 를 의심했으면
  멀쩡한 코드를 고칠 뻔했다. **tsc 통과 + 런타임 ReferenceError = 빌드 캐시부터 의심.**
- **토큰 한 파일 변경이 26개 파일 670곳에 즉시 반영** — 주간 리포트 ≤10.5px 비중이
  코드 한 줄도 안 건드리고 28% → 1% 가 됐다. TK 색상 토큰과 같은 구조적 레버임이 재확인됐다.
- **커밋 훅이 브리핑에서 색상 하드코딩 7줄을 지적** — `#7c8db0`·`#1b2130`·`#1a1f30`·`#33415588`.
  전부 기존 값이고 3단계(색 역할 고정) 대상이라 지금은 남겼다. TK 에 임의 추가하지 않는다(원칙).

## 2단계 결정 기록 (2026-09-04)

### 프리미티브를 5개 → 3개로 줄인 이유
계획서엔 `PageHead·Verdict·Section·Row·Note` 5개였으나 **3개만** 만들었다.
- `PageHead` — `Verdict` 의 eyebrow 가 같은 일을 한다. 둘을 두면 "제목은 어디에 쓰지"가 새 문제가 된다.
- `Row` — 자산 보유 행(35요소)과 브리핑 추천 카드(10요소)는 구조가 너무 달라, 지금 추상화하면
  props 10개짜리 괴물이 된다. **두 번째 소비자가 생길 때** 만든다(§2 단순성).

### `Verdict` 는 페이지당 하나 — 코드로 강제하지 않은 이유
마운트 카운터는 React StrictMode 이중 마운트에서 오탐이 나고, 한 줄 규칙 때문에 렌더 사이드이펙트를
넣는 건 배보다 배꼽이다. 컴포넌트 헤더 주석에 규칙을 적고 리뷰에서 본다.

### 화면검증이 잡은 내 결함 2건 (배포 전)
- 🔴 **"평가손익 ₩0 (0.0%)"** — 시세가 오기 전 `evalKrw` 가 매입가로 폴백해 손익이 0 이 됐다.
  footer 에 경고를 달아뒀지만 **헤드라인이 '본전'이라고 단언**했다 — *배지·툴팁은 숫자를 상쇄하지 못한다*.
  `priceStatus`(idle/loading/done/error)가 **이미 있었는데 안 쓰고 있었다** — '있는데 안 쓴 데이터' 재발.
  → 시세를 못 믿으면 **손익 숫자를 아예 그리지 않는다**. 대시보드도 같은 규칙으로 갈랐다.
  ⭐ 교훈: 폴백이 있는 값을 헤드라인에 올릴 땐 **폴백 발동 여부를 먼저 물어야 한다.**
     경고를 덧붙이는 걸로 끝내면 안 된다.
- 부호 두 종류 혼재(`−₩283만 (-8.6%)`) — `toFixed()` 는 하이픈, 금액은 마이너스기호.
  `Math.abs` + 부호 한 글자로 통일(자산·대시보드).

### 커밋 훅 오탐 수정 (scripts/precommit-guard.mjs)
신규 파일 `Screen.tsx` 가 차단됐는데 걸린 건 **주석 안의 hex**("구 카드 배경이 '#12151f' 였다"는 실측 근거).
주석의 hex 는 화면을 칠하지 않는다 → `isCommentLine()` 추가(줄 **시작**이 주석일 때만 제외).
검증: 주석만 있으면 exit 0, 실제 스타일 값(`#ff00aa`·`fontSize: 9`)은 exit 1.
⛔ `--no-verify` 로 우회하지 않았다 — **훅이 부정확하면 고치는 게 맞지, 끄는 게 아니다.**

### 승패 해부실 — `mine`(내 보유)을 Verdict 에서 뺀 이유
`mine.size` 는 **미로그인·조회실패·보유0종이 전부 0** 이라 셋을 구분하지 못한다
(이 화면엔 로그인 상태 state 자체가 없다). 모르는 걸 0 으로 그리면 거짓말이 된다.

### 알면서 안 고친 것 → 3단계
`weekly-report` 의 `pcol()` 이 **초록=상승·빨강=하락(미국식)** 이고 22곳에서 쓴다.
프로젝트 규약('주가 등락·내 손익'은 한국식)과 반대인 게 코드로 확인됐다.
그런데 헤드라인만 뒤집으면 **바로 아래 KPI 8종과 정반대로 읽힌다**(같은 화면 안 모순은 이 앱이 두 번 사고 낸 유형).
→ Verdict 도 같은 `pcol` 을 쓰게 두고, 규약 통일은 3단계에서 화면 단위로. *일괄 치환하지 말고 가려라.*

## 3단계 결정 기록 (2026-09-04)

### Pretendard 실측 판정표 (npm 레지스트리 + tarball 직접 측정)
| 항목 | 실측값 |
|---|---|
| 버전·라이선스 | 1.3.9 · **OFL-1.1** (상용 배포 가능) |
| variable 통짜 woff2 | **2,009 KB** — 학생 모바일 첫 로드에 부담 |
| variable dynamic-subset | **92조각 · 총 3.1MB** (조각당 31~37KB) · CSS 54.5KB |
| 판정 | 도입 가능. 통짜 대신 **dynamic-subset**(브라우저가 unicode-range 로 쓰는 글자 든 조각만 받음) |
⚠️ **실제 전송량은 실측하지 않았다** — 브라우저에서 재야 안다. 도입 시 함께 측정할 것.
⚠️ 폰트 교체는 **글자 폭을 바꿔** 방금 맞춘 375px·1280px 레이아웃을 다시 검증해야 한다 →
   픽셀 불변인 색 작업을 먼저 끝내고 별도 커밋으로 분리했다.

### 모바일 — auto-fit 이 만능이 아니다
처방이 두 부류로 갈렸다. 이걸 구분 못 하면 데스크톱이 망가진다.
- **(가) auto-fit 이 이미 있고 하한만 큰 경우** → `minmax(min(N, 100%), 1fr)`.
  min() 안의 100%가 그리드 컨테이너 폭으로 해석돼 좁을 땐 트랙이 줄고, 데스크톱에선 N 을 그대로 고른다.
- **(나) 비율 그리드(6fr/4fr·3fr/2fr)** → auto-fit 은 **오답**. 비율이 소멸해 6:4 가 5:5 가 된다.
  미디어쿼리로 모바일에서만 1열로 접어야 데스크톱이 그대로 남는다.
→ `globals.css` 에 모바일 유틸 7개(.m-stack/.m-wrap/.m-1col/.m-full/.m-wauto/.m-hide/.m-scroll).
  인라인 style 위주라 화면마다 @media 를 둘 자리가 없었다. **!important 는 이 파일 밖에서 쓰지 말 것.**

### 색 — 일괄 치환하지 말고 가려라(실제로 그래야 했다)
`weekly-report` 의 `pcol()` 을 통째로 뒤집었으면 **3곳이 오히려 틀렸다** —
외국인·기관 순매수(:424,425)와 전월세 전환율 스프레드(:612)는 '가격'이 아니라 판정 지표다.
→ 함수를 둘로 갈랐다: `pcol`(등락·손익, 한국식) / `jcol`(판정, 초록=좋음).

**인쇄본에 두 번째 SSOT 가 숨어 있었다** — `printReport()` 의 `pc()` 24곳 + 막대 배경 +
범례 문구 "상승 초록/하락 빨강". 화면만 고쳤으면 학생이 뽑은 종이와 화면이 정반대가 됐다.
인쇄본은 흰 배경이라 다크 토큰을 못 써서 인쇄용 값을 따로 두고 `토큰예외:` 사유를 남겼다.
⭐ 교훈: **색 함수를 고칠 땐 그 화면의 인쇄·내보내기 경로를 함께 찾아라.**

### 같은 카드 안 자기모순 2건

  우열은 등락이 아니므로 **색이 아니라 명도**로 바꿨다(등락 색과 충돌 회피).
