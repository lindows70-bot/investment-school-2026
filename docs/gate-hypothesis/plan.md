## 왜 "조합 탐색"을 하지 않는가 (먼저)
측정된 신호가 14개 → 2개 조합 91 · 3개 조합 364 = **455가지**.
방금 실측한 20봉 전방수익률 **표준편차 11.23%**(n=12,165) 기준:

| 표본 | 표준오차 | 455개 중 최고치 기대(≈3σ) |
|---|---|---|
| 200건 | 0.79%p | **+2.38%p** |

즉 **진짜 엣지가 0인 신호를 455가지로 섞어도 1등은 +2.4%p** 로 나온다 — 우리 최고 셋업(엘리펀트 +2.77)과 사실상 구분 불가.
그래서 이번 작업은 **탐색이 아니라 검정**이다. 셀 수를 미리 8개로 못박는다.

## 가설 (1차, 사전 등록)
> **우리 표본에서 돈을 버는 건 트리거가 아니라 상태다.**
> 따라서 상태 게이트를 통과한 구간에서만 트리거를 쓰면, **단독으로 음수인 트리거가 양수로 뒤집힌다.**

근거 — 대표본 생존자는 전부 상태형이고, 트리거는 전부 음수다(기존 측정):

| 유형 | 셋업 | edge20 | n |
|---|---|---|---|
| 상태 | timeFilled | +1.04 | 3,166 |
| 상태 | greenState | +0.87 | 3,026 |
| 트리거 | greenTurn | −0.36 | 161 |
| 트리거 | bullDiv | −0.90 | 477 |
| 트리거 | pullback | −0.95 | 375 |

그리고 이미 한 번 재현됐다 — `prime`(= green 게이트 ∧ (bullDiv ∨ pullback))이 **+1.33**.
**이번 작업의 본질은 "prime 이 표본 우연이었는지"를 안 본 종목에서 확인하는 것이다.**

## 설계 — 종목 분할 hold-out
- **in-sample 80종** = 지금까지 모든 측정이 나온 KR 40 + US 40 (오염됨)
- **out-of-sample 120종** = 새로 추가하는 KR 60 + US 60 (**한 번도 안 본 데이터**)
- 둘을 **따로** 보고한다. 판정은 **OOS 로만** 한다.

## 측정 셀 — 8개 (탐색 금지, 전부 사전 지정)
게이트 2개 × 트리거 2개 + 단독 4개. **이 목록에 없는 조합은 이번에 재지 않는다.**

| | 정의 |
|---|---|
| G1 | 신호등 green = `EMA112 > EMA224 && 구름 위` (entryTiming SSOT 동일 정의) |
| G2 | timeFilled = 기간 조정 충족 (`readTimeCorrection`) |
| T1 | pullback (라쉬케 stage4 첫 눌림목) |
| T2 | bullDiv (상승 다이버전스) |
| 조합 | G1∧T1 · G1∧T2 · G2∧T1 · G2∧T2 |

## 통과 기준 — 측정 전 확정 (스크립트에 하드코딩)
**1차 검정은 단 하나다: `prime = G1 ∧ (T1 ∨ T2)` 의 OOS 재현.**
(셀 하나만 1차로 두는 이유 — 4개를 다 1차로 두면 best-of-4 기대 최고치가 ≈+0.8%p 라 +1.0 기준이 소음과 가깝다.)

```
① OOS 절사 edge20        ≥ +1.0%p
② KR·US 부호 동일         ← 오늘 RSI-BB 를 죽인 기준
③ n                       ≥ 200
④ 최다 종목 점유          ≤ 30%
⑤ 레짐 3개 중 양수         ≥ 2개
⑥ 게이트 기여 Δ = edge(G∧T) − edge(T)  > 0
```
나머지 7셀은 **탐색적(secondary)** 으로만 보고하고, 통과 판정에 쓰지 않는다.
