> 상태: **v1 구현 완료(2026-07-26)** · 사용자 확정: 클라우드 코워크에서 가져오지 않고 **앱에서 전부 해결**
> 근거: 클라우드 실측 명세(`cloudenvspec.md`) — 아웃바운드 허용목록이라 POST 업로드 불가·트리거/스킬 프롬프트 모순·카톡은 자기채팅만.
> 앱 단독이면 이 제약이 전부 소멸(배포 자체가 불필요 — 학생이 로그인해서 봄).

## 1. 최종 아키텍처 (v1 구현됨)

```
GET /api/weekly-report[?userId=]   (로그인 필수 · ?userId=는 teacher만)
  ├─ 공통 시장 섹션  weekly-report-common-v1:{일자}  6h 캐시 · 전원 공유
  │    지수 7종 주간 등락(야후) · 매크로 국면(fetchMacroData SSOT) · 국가 변동성(computeCountryVol)
  │    이슈(market-catalyst 캐시 읽기만 — 콜드면 생략)
  └─ 개인 섹션      weekly-report-me-v1:{uid}:{일자}:{fp}  6h 캐시 · 보유 지문 무효화
       보유 병합(분할매수 합산) → 현재가(/api/stock-price 배치 40청크 · KR/US/CRYPTO SSOT)
       주간 수익률(getTechCandles 캐시 · 크립토=야후 -USD 근사)
       섹터(유니버스 캐시 → getSector 7d 폴백) · 신호(user_daily_briefings 최신일 = Jarvis 크론 적재분)
       타점(getEntryTimings) · 리스크 5종 · 캘린더(event-calendar 쿠키 포워드 — 본인 조회만)

/weekly-report  페이지 — ①시장 ②매크로·변동성 ③이슈 ④내 포트폴리오 ⑤섹터 기여 ⑥리스크 ⑦캘린더
  + 🖨️ PDF 저장(새 창 라이트 문서 → window.print — ResearchReport 패턴, 파일명 2026투자학교_주간리포트_{이름}_{날짜})
  + teacher는 학생 선택 드롭다운(전원 미리보기·인쇄)

사이드바: 📌 매일 → 📄 주간 리포트
```

**분석은 전부 앱 SSOT(제2원칙)** — Python(portfolio.py) 재계산 없음. 같은 종목=앱 화면과 같은 값.

## 2. 클라우드 명세 5대 지적 → 앱 해결

| 명세 지적 | 앱 처리 |
|---|---|
| 자산군 `CLS_COLOR` KeyError | `getAssetType` SSOT — 하드코딩 딕셔너리 불필요 |
| 반도체 집중도 = 티커 3개 리터럴 | 유니버스 `industry`(/semiconductor/i) + 대표 티커 12종 폴백 |
| 주간 기준일 티커별 07/16~07/17 혼재 | **`weeklyFrom()` 단일 함수** — 직전 금요일 종가(휴장 시 그 이전 거래일), 전 지표 동일 |
| `avg_fx`(매입환율) 컬럼 없음 | 현재 환율 근사 + **"근사치" 정직 표기**(화면·PDF 각주) |
| 현금 미등록 | 리스크 게이지에 **"미등록"** 레벨 — 잰 척 안 함 |

리스크 5종 임계값은 클라우드 portfolio.py와 동일(반도체 40/60 · 상위3 55/70 · 환노출 50/75 · 코인 20/35 · 현금 <10/<5·≥30).

## 3. 확정 결정

- **색상 = 앱 규칙 통일**(상승 초록/하락 빨강) — 화면·PDF 동일, PDF 헤더에 표기 명시
- **현금·매입환율 = v1 스키마 변경 없음**(정직 표기로 갈음)
- **교사 대리 조회 시 캘린더 생략** — event-calendar가 세션 기준이라 쿠키 포워드하면 교사 본인 캘린더가 나옴(잘못된 데이터) → null + 안내
- **캐시 박제 금지 가드**: 공통=지수 과반 실패 시 / 개인=가격 실측 50% 미만 시 저장 안 함
- 폐기: Supabase Storage·업로드 라우트·weekly_reports 테이블·서명 URL·클라우드 pull 구조 (전부 불필요해짐)
