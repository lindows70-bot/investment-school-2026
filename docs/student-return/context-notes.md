# 학생 복귀(2단계) 컨텍스트 노트

## 미확인 가정(사용자 "네 권고대로" — 확인받지 않고 내가 정한 것)
- 메시지 채널은 **카톡 문구 생성(선생님이 붙여넣기)** 로 시작한다. 푸시는 학생이 먼저 앱을 열어 권한을 줘야 하는데 지금 학생은 앱을 안 연다 — 순서가 거꾸로다. 이메일은 학생이 안 읽을 가능성이 크고 발송 인프라가 필요하다. 반 단톡방이 있다는 가정이다.
- 로그인 유지는 **역할이 아니라 기기 상황(standalone)** 으로 가른다. 공용 PC 에서 설치 앱으로 쓸 일은 없고, 선생님 설치 앱도 같이 혜택을 본다(9/26 history: 선생님 화면 global 로그아웃이 설치 앱에 불리하다는 기록).
- 순위 변화는 주 1회(월요일)면 충분하다 — 매일 저장하면 변화가 잡음이 된다.

## 판정표(Phase 0)
| 항목 | 판정 | 근거 |
|---|---|---|
| 순위 이력 | ❌ 없음 | `app_cache`·DB 어디에도 리그 스냅샷 없음(2026-10-09 grep) |
| 접속 기록 | ✅ `student_visits`(user_id·visit_date·first_path) | 9/26~ 15행 |
| standalone 판별 | ✅ `matchMedia('(display-mode: standalone)')` + iOS `navigator.standalone` | 표준 API · 폰 실측은 사용자 기기에서 |
| 카톡 전송 API | ❌ 범위 밖 | 카카오 비즈 채널·알림톡은 사업자 인증 필요 |

## 기각한 안
- **역할별 유휴 로그아웃(학생만 끄기)** — 학생도 학교 공용 PC 에서 쓸 수 있다. 기기 상황이 더 정확하다.
- **IDLE_MS 를 7일로** — 공용 PC 보호가 사라진다. standalone 예외가 목적에 맞다.
- **매일 스냅샷** — 하루 변화는 잡음. 주간이 리그 원칙(천천히 부자)과 맞다.
- **LLM 으로 소식 문구 생성** — 학생 이름·순위·수익률은 개인 데이터(CLAUDE.md 절대 원칙). 결정론 템플릿으로 충분하다.
