# 학생 복귀(2단계) — 학생이 앱을 다시 열게

## 목적
학생 8명 중 7명이 2주간(9/26~10/9) 한 번도 앱을 열지 않았다(`student_visits` 15행 중 선생님 14회 · 학생 1회). 종목을 넣은 6명도 마찬가지다. 그동안 기능은 계속 늘었는데 **열 이유와 열기 쉬움**이 없었다. 이 단계는 기능을 더하지 않고, ①로그인이 풀리지 않게 ②첫 화면에서 할 일이 보이게 ③매주 돌아올 이유(순위 변화·소식)를 만든다.

## 착수 전 확인 6줄(사용자 "네 권고대로 · 2단계 시작" — 아래는 내 추측으로 채웠다 · 틀리면 여기서 갈린다)
```
결과    : 설치 앱 유휴 로그아웃 해제 · 보유 0 학생 홈 온보딩 카드 · 주간 리그 스냅샷(순위 변화) · 선생님용 '이번 주 소식' 카톡 문구 생성 화면
사용자  : 학생(①②③) · 선생님(④ 문구를 단톡방에 붙여넣는다)
왜 지금 : 학생 접속 2주 1회 — 기능보다 복귀가 먼저
성공    : 10/24 학생 모드 4주 측정에서 학생 접속일 ≥ 2명 × 2일 이상(지금 1명 × 1일) · 선생님이 월요일 문구를 실제로 보냄
제약    : 개인 데이터는 LLM 에 보내지 않는다(문구는 결정론 템플릿) · 순위 변화는 저장된 스냅샷만(추정 금지) · 공용 PC 유휴 로그아웃은 유지
범위 밖 : 푸시 알림(권한 흐름·학생이 먼저 열어야 함) · 이메일 발송 · 수업 과제 체크(2-3 · 다음 단계) · 증권사 캡처 자동 등록
```

## 데이터
| 있는 것 ✅ | 없는 것 ❌ |
|---|---|
| `/api/school-league` 순위·수익률(매번 계산 · SSOT `studentTotalReturn`) | 순위 **이력**(저장소 없음 → 변화 못 보여줌) |
| `student_visits`(일별 첫 경로) | 선생님 화면 열람 기록 |
| `public/sw.js`(설치형 PWA 기반) | 푸시 구독(범위 밖) |
| 라운지 공지(선생님만 작성) | 과제·완료 체크(범위 밖) |

## 설계
1. **2-1 로그인 유지** — `IdleTimer` 가 `display-mode: standalone`(홈 화면 설치 앱)이면 유휴 타이머를 걸지 않는다. 브라우저 탭(공용 PC)은 30분 그대로. 역할이 아니라 **기기 상황**으로 가른다 — 선생님 설치 앱도 같이 산다. 서버 토큰은 Supabase 기본 만료.
2. **2-4 온보딩 카드** — 보유 0 이면 홈 맨 위 인사 아래에 한 카드만: "종목 하나만 적어도 리그에 들어와요 · 2분" + 기록하기 버튼. 기존 '아직 기록한 종목이 없어요' 줄을 키우고 이유를 붙인다(새 화면 없음).
3. **2-6 주간 리그 스냅샷** — 매주 월요일 06:30 KST 크론이 `/api/school-league` 결과(이름·순위·총수익률·보유 수)를 `league-snap-v1:{YYYY-MM-DD}` 로 저장(날짜 키 → `PURGE_RULES` 에 400일 보존 등록 · 캐시날짜 규칙). 리그 화면 '내 순위' 아래에 "지난주 N위 → 이번 주 M위"를 **스냅샷이 2개 이상일 때만** 표시(없으면 아무 말도 안 한다).
4. **2-2 '이번 주 소식' 문구** — 선생님 화면(관리자 대시보드)에 카드 하나: 월요일 스냅샷 2개를 비교해 결정론 템플릿으로 카톡용 문구를 만든다 — 상위 3·순위 상승 1·시장 한 줄(코스피 주간 등락 · 네이버)·이번 주 일정 2개(FOMC·CPI·내 종목 실적) · 앱 링크. **복사 버튼**만. LLM 없음(개인 데이터). 학생 이름은 실명 그대로(단톡방은 이미 서로 아는 사이) — 금액은 넣지 않는다(리그 원칙).
