# 🏛️ 우선주 축 — 컨텍스트 노트 (결정 기록)

## 데이터 실측 판정표 (2026-08-22 · yahoo-finance2 로컬 실행)

> ⚠️ 로컬 bare `fetch` 는 야후가 **401** 로 전부 막았다. 프로덕션과 같은 `yahoo-finance2`(쿠키·crumb 처리)로 호출해야 값이 나온다.
> 표본: Strategy 우선주 4 · 타사 우선주 3(BAC-PL·NLY-PF·AGNCN) · 보통주 10 · ETF 4 · KR 4.

| 후보 신호 | 결과 | 판정 |
|---|---|---|
| `quoteType` | 우선주·보통주 **둘 다 `EQUITY`** | ❌ 구분 불가 |
| `longName` | 우선주 STRC/STRK/STRF/STRD 전부 **"Strategy Inc"** — 보통주 MSTR과 **완전히 동일** | ❌ 단독 사용 금지 |
| `shortName` | "Strategy Inc - 8.00% Series A P" 처럼 발행사명 + 시리즈. **32자에서 절단** | ✅ 유일한 이름 신호(단, 절단 주의) |
| `marketCap` | 우선주 7/7 **null** · 보통주 10/10 **값 있음** · ETF null | ✅ 강력(ETF는 quoteType으로 선배제) |
| `sharesOutstanding` | **오염** — NLY-PF 13.1억주(보통주 NLY 7.5억주보다 큼) · AGNCN 4.8억주 · STRD 1,176만주 | ❌ 신뢰 불가 |

### 여기서 나온 두 가지 결정적 사실

1. **`longName` 이 보통주와 같다.** 이름만 보고 판정하면 MSTR도 우선주가 된다. → `shortName`(시리즈 포함)과 `longName`(발행사)을 **분리해 쓴다**.
2. **`sharesOutstanding` 에 발행사 값이 섞여 온다.** 앞서 화면검증에서 발견한 *"STRD만 안전 28(위험), 나머지 셋은 50(보통)"* 의 근본 원인이 이것이다.
   `fcfCover = 회사 전체 FCF ÷ (그 시리즈 배당 × 주식수)` 인데 주식수가 시리즈 것이 아니다 — **분자와 분모가 다른 것을 잰다.**
   STRD만 값이 와서 −184.87 이 계산됐고 그래서 혼자 감점됐다. 즉 **리스크 차이가 아니라 데이터 유무 차이**였다.
   → 우선주는 `fcfCover` 를 **계산하지 않는다**(null). 그 결과 4종의 등급 불일치가 원인에서 사라진다.
   *STRD 가 실제로 넷 중 가장 위험한 건 맞지만(비누적·후순위) 우리 앱이 그걸 맞힌 게 아니라 우연이었다.*
   🔁 KR 도 같다 — 005935(삼성전자우) `marketCap` 이 1,365조로 보통주(1,848조)의 74%다. 명백한 오염.

## 채택한 판정 규칙

```
US  : quoteType === 'EQUITY'  &&  marketCap == null
      && ( 우선주 키워드(%·Series·Preferred·Depositary·Cum·Perpetual·Variable Rate)
           || shortName 이 longName 을 접두로 포함하며 더 길다 )
KR  : 6자리 코드 && 끝자리 ≠ 0 && 이름에 (1P)/(2P) 또는 '우'/'우B'
```

표본 결과 **우선주 7/7 적중 · 보통주 10/10·ETF 4/4·KR 보통주 2/2 오탐 0**.
키워드 단독으로는 BAC-PL("…Non" 에서 절단)·NLY-PF("…Inc 6")를 놓치는데, `marketCap == null` 이 그 둘을 건진다.
접두 조건 단독은 BRK-B("Berkshire Hathaway Inc. New")류가 오탐이라 **AND 로 묶었다**.

## 채택하지 않은 안과 이유

| 안 | 기각 사유 |
|---|---|
| **A안 — 노출만(유니버스에 4종 추가)** | 지금 발견한 "같은 발행사인데 보통 vs 위험"이 그대로 학생 화면에 올라간다. 노출은 결함을 고친 뒤에. |
| 티커 하드코딩 목록(`PREFERRED = ['STRC',…]`) | 제1원칙 위반. 학생이 BAC-PL 을 검색하면 그대로 뚫린다. |
| 우선주에도 안전성 점수를 매긴다 | 입력(배당성향·FCF커버·연속인상·CAGR)이 전부 null 이라 **항상 기본값 50 "보통"** 이 나온다. 근거 없는 등급 = ⛔가짜 정밀. → `null` 로 두고 배지를 없앤다. |
| 액면가를 표에 박는다(우선주는 보통 $25/$100) | 제1원칙. **연배당금 ÷ 쿠폰율**로 원문에서 파생한다(STRK 8÷0.08=$100·STRF 10÷0.10=$100 — 실측 일치). |
| 우선주→보통주 티커 자동 연결(STRC→MSTR) | 야후 응답에서 파생 불가. 억지 매핑 대신 **발행사명**만 밝힌다. |
| 배당 성장률·YoC 를 그대로 보여준다 | 쿠폰이 고정(STRK 8%)이라 성장률 0%가 '나쁜 배당주'로 읽힌다. 사실은 **해당 없음**이다. |

## 임계값 근거

- `isTrapWarning` = 배당률 ≥8% **또는** 액면 대비 ≤−10% **또는** 변동금리. 우선주라고 전부 경보를 달면 BAC 6% 우선주까지 함정이 되어 경보가 무의미해진다.
- 액면 추정은 1~5,000 범위 + 쿠폰율 0.5~30% 안에서만 계산(파싱 오독 방어).

## 검증에서 발견한 것

- STRC 는 **변동금리** — 회사가 매달 이율을 조정한다. 지금 12.6%를 미래로 투사하는 YoC 는 우선주에 쓸 수 없는 숫자였다.
- 액면 괴리가 4종의 배당률 차이를 설명한다 — STRF 액면 대비 −0.4%(10.24%) vs STRD −27.5%(14.15%). **같은 10% 쿠폰인데 배당률이 다른 이유**가 여기 있고, 이게 학생에게 줄 진짜 교육 내용이다.
