## 채택하지 않은 안과 이유
- **월말 스냅샷을 DB에 저장** — 과거분이 없어 지금 시작하면 5~7월이 비고, 크론·테이블·백필이 전부 필요. 캔들 재구성이 즉시 전 기간을 준다 → 기각.
- **원가를 매입일 환율로 환산**(fxAttribution 방식) — 더 정확하지만 마지막 달 누적이 대시보드 평가손익(toKrw=현재 환율 환산)과 불일치 → 같은 화면에 '손익' 두 값이 생겨 제2원칙 위반. 월말 환율 통일로 결정.
- **클라이언트에서 종목별 tech-chart 22회 호출** — 요청 폭주 + XRP 미지원 → 서버 1회 POST 로 기각.
- **개인 결과를 app_cache 에 캐시** — 개인 계좌 경계 원칙 위반 소지 → 캔들 공유 캐시만 쓰고 결과는 무캐시.
- **실현손익(매도분) 포함** — transactions 조인 + 매도가 시점 재구성 필요. v1 은 보유분만, 캐비엇 명시. 필요해지면 v2.

## 검증에서 발견한 것
- API 스모크(대표 4로트): 5월 -37만 → 6월 -9만 → **7월 -242만(최대 하락)** → 8월 -21만. 사용자 기억("7월에 폭락")과 정합. 수기 검산 오차 ±2%(환율·종가 시점차).
- 응답 4.7초(캔들 무캐시 첫 호출) — 이후는 tech-chart-v1 30분 캐시가 흡수.
- 실화면: 캐비엇 텍스트 렌더 확인 = 데이터 분기 진입. 단 dev 세션에서 svg 막대·라벨의 육안 확인은 렌더러 프리즈로 실패(기지의 dev 전용 Recharts 이슈와 동일 계열) — **프로덕션 육안 확인은 사용자 몫으로 남김**.
- 마지막 달 누적 == 대시보드 평가손익은 구조적으로 보장(같은 종가·환율 관례)이나 시세 소스 시점차로 소액 차이 가능 — KR은 둘 다 네이버 종가라 일치, US는 야후 쿼트 vs 야후 캔들.
- **배포 후 화면검증에서 발견**: 누적 끝 -522만 vs 평가손익 카드 -530만 — 원인은 환율 소스(KRW=X 캔들 전일종가 1,427.93 vs 대시보드 실시간 1,442). 현재 월만 클라이언트가 보낸 usdKrwNow 로 계산하게 수정(과거 월은 캔들이 정답 — 실측으로 과거 월 불변 확인).
- 사용자 기억 최종 판정: 5월 **+196만 플러스** 맞음. 6월은 기억과 달리 이미 -246만. 7월 -442만 최대 하락.
